## СТОЛП 3: КАЧЕСТВО КОДА И BEST PRACTICES

**Проверяем современность и эффективность:**

✅ **Паттерны Python 3.12+:**
- Используются ли match/case вместо if/elif?
- Используются ли type hints везде (PEP 484)?
- Используются ли dataclass / pydantic вместо наивных классов?
- Правильно ли работает async/await (если используется)?

✅ **SOLID принципы:**
- **S** — Single Responsibility: каждый класс/функция делает одно?
- **O** — Open/Closed: легко расширяемо, сложно редактируемо?
- **L** — Liskov Substitution: полиморфизм правильно реализован?
- **I** — Interface Segregation: интерфейсы узко специализированы?
- **D** — Dependency Injection: зависимости инъецируются?

✅ **DRY — Don't Repeat Yourself:**
- Есть ли дублирование логики 3+ раза?
- Можно ли вынести в общую функцию?

✅ **Цикломатическая сложность:**
- Функции не более 10 ветвлений?
- Нет ли функций с 20+ строк if/elif цепочек?

✅ **Оптимизация:**
- N+1 запросы (если есть работа с данными)?
- Неоптимальные алгоритмы (O(n²) когда можно O(n log n))?
- Утечки памяти или неправильное управление ресурсами?
- Лишние ререндеры или пересчёты?

✅ **Мёртвый код:**
- Неиспользуемые функции, классы, модули?
- Неиспользуемые импорты?
- Переменные, которые никто не читает?

**Инструмент проверки:** Результаты `python3.12 operations/scripts/quality/run_suite.py full`
- `pylint` / `flake8` — стиль и ошибки
- `black` — форматирование
- `mypy` — типизация
- `radon` — цикломатическая сложность
- `bandit` — безопасность

**Вердикт по каждому пункту:**
- Что работает хорошо (примеры хороших паттернов)
- Где нужны улучшения (конкретные места и решения)

## СТОЛП 4: ГИГИЕНА КОДА — БЕЗ ЗАГЛУШЕК И ХАРДКОДА

**КРИТИЧНО! No BS политика проекта:**

❌ **Запрещено в продакшене:**
```python
TODO("реализуем позже")
FIXME: неправильный результат
HACK: обход для теста
try: ...
except: pass  # скрыть ошибку
if some_condition:
    return None  # без обработки
# ... (три точки вместо реализации)
```

❌ **Хардкод (магические числа, URL, пути):**
```python
url = "http://192.168.1.1:8080"  # вместо os.getenv
token = "sk_live_abc123xyz"  # СЕКРЕТ В КОДЕ!
path = "/home/user/data"  # абсолютный путь
TIMEOUT = 30  # магическое число
```

✅ **Допускается только:**
- В тестах (моки, fixtures)
- В явно помеченных прототипах (v0, draft, experimental)
- Задокументировано в TASK карточке как известный долг

**Поиск заглушек:**
```bash
grep -rn "TODO\|FIXME\|HACK\|pass\|\.\.\..*$" src/
grep -rn "except.*pass" src/
grep -rn "return None" src/ | grep -v "# expected"
grep -rn "# " src/ | grep -E "^#\s+\.\.\.$"
```

**Поиск хардкода:**
```bash
grep -rn "http://\|https://\|192\.168\|127\.0\.0\.1" src/ | grep -v test
grep -rn "sk_live_\|sk_test_\|api_key.*=" src/ | grep -v test
grep -rn "password.*=\|secret.*=" src/ | grep -v test | grep -v ".env"
```

**Поиск чувствительных данных:**
```bash
pip install detect-secrets
detect-secrets scan src/ --all-files
```

**Для каждой находки указать:**
- Файл, строка
- Тип проблемы (заглушка / хардкод / мусор / секрет)
- Статус: критична ли она (продакшен код) или допустима (тест)?
- Действие: удалить / TASK / вынести в .env

## СТОЛП 5: ТЕСТИРОВАНИЕ И НАДЁЖНОСТЬ

**Проверяем полноту и качество тестов:**

✅ **Покрытие по модулям:**
- Все ли модули в src/ имеют unit-тесты?
- Для каждого модуля: какой % строк покрыто?
- Целевое: ≥80% для критических модулей

✅ **Типы тестов:**
- Unit-тесты (каждая функция работает сама)?
- Integration-тесты (компоненты взаимодействуют правильно)?
- End-to-end тесты (система работает целиком)?

✅ **Качество тестов:**
- Есть ли тесты на edge cases (пустой вход, None, граничные значения)?
- Есть ли тесты на ошибки (исключения, timeout)?
- Или только happy path?
- Есть ли тесты на конкурентность (race conditions)?

✅ **Связность TEST:**
- Каждый BR_* имеет TEST карточку?
- Каждый TEST имеет `verifies` ссылку?
- Каждый TEST имеет `execution: automated` + `automated_evidence`?

✅ **Flaky тесты (нестабильные):**
- Есть ли тесты, которые иногда проходят, иногда падают?
- Причина: недетерминированный порядок, timing, мок-зависимости?
- Это БЛОКИРУЕТ мерж до исправления!

✅ **CI/CD pipeline:**
- Запускаются ли тесты на каждый push?
- Блокирует ли CI мёртвый код / низкое покрытие?
- Есть ли проверка типов, линта, безопасности?

**Команды проверки:**
```bash
# Все проверки
python3.12 operations/scripts/quality/run_suite.py full

# Только тесты с покрытием
pytest --cov=src --cov-report=html operations/tests/

# Найти flaky тесты
pytest -v --tb=short operations/tests/ 2>&1 | grep FAILED

# Проверить, какие TEST карточки есть
ls -la work/tests/test_*.md
```

**Вердикт:**
- Какие части бизнеса покрыты / не покрыты тестами
- Список flaky тестов (если есть)
- Что нужно добавить в CI/CD

## СТОЛП 6: ТРАССИРУЕМОСТЬ И СВЯЗНОСТЬ

**Проверяем полную цепочку от требования к коду:**

✅ **Цепочка BR → TASK → Code → TEST должна быть полной:**
```
BR_001 (требование в specifications/business_requirements.md)
  ↓ implements (TASK карточка ссылается сюда)
TASK_003 (в work/tasks/task_003_*.md)
  ↓ code (TASK указывает allowed_paths)
src/orchestration/orchestrator.py (реальная реализация)
  ↓ covers (TEST карточка тестирует это)
TEST_003 (в work/tests/test_003.md)
  ↓ verifies (TEST ссылается на BR)
BR_001 ✅ (замкнулся цикл)
```

✅ **Проверка целостности:**
- Все BR_* имеют `implements` ссылку на TASK?
- Все TASK имеют `traces_to` на BR_*?
- Все TASK имеют `allowed_paths`?
- Все TEST имеют `verifies` на BR_* или TASK?
- Все TEST имеют `execution: automated` + `automated_evidence`?

✅ **Мёртвый код:**
- Есть ли модули/функции, которые никто не импортирует?
- Есть ли TASK без `allowed_paths` (висящие карточки)?
- Есть ли код, который реализует BR, но про этот BR нет TASK?

✅ **Граница модулей:**
- Понятны ли границы ответственности каждого модуля?
- Соответствуют ли они описанию в architecture_baseline.md?
- Нет ли "утечек" ответственности (один модуль делает слишком много)?

**Инструмент проверки:**
```bash
# Открыть автоматический отчёт
cat generated/traceability_matrix.md

# Найти потенциально мёртвый код
find src -name "*.py" | while read f; do
  if ! grep -r "from.*import.*$f\|import.*$f" src/ --include="*.py" 2>/dev/null >/dev/null; then
    echo "Possible dead: $f"
  fi
done

# Проверить TASK без allowed_paths
grep -L "allowed_paths:" work/tasks/task_*.md

# Проверить orphaned TEST (TEST без verifies)
grep -L "verifies:" work/tests/test_*.md
```

**Вердикт:**
- Целостна ли цепочка BR → TASK → Code → TEST?
- Есть ли разорванные звенья (нужна TASK / нужен TEST)?
- Есть ли мёртвый код?

## ПОЛЕЗНЫЕ КОМАНДЫ

```bash
# === ДИАГНОСТИКА ===

# Все проверки качества (ГЛАВНЫЙ СКРИПТ)
python3.12 operations/scripts/quality/run_suite.py full

# Покрытие тестами
pytest --cov=src --cov-report=html operations/tests/

# Результаты последних проверок
cat generated/health_check_report.md

# Трассируемость требований
cat generated/traceability_matrix.md

# === ПОИСК ПРОБЛЕМ ===

# TODO, FIXME, заглушки
grep -rn "TODO\|FIXME\|HACK" src/
grep -rn "except.*pass\|return None" src/
grep -rn "^#\s*\.\.\." src/

# Хардкод
grep -rn "http://\|https://\|192\.168\|127\.0\.0\.1" src/ | grep -v test

# Потенциальные секреты
detect-secrets scan src/

# Мёртвый код (неиспользуемые модули)
find src -name "*.py" | while read f; do
  if ! grep -r "from.*import\|^import" src/ --include="*.py" | grep -q "$f"; then
    echo "Dead: $f"
  fi
done

# === КОНКРЕТНЫЕ ПРОВЕРКИ ===

# Установить зависимости
python3.12 -m pip install -r operations/quality/requirements_dev.txt

# Форматирование
black src/

# Типизация
mypy src/

# Линт
pylint src/

# Сложность
radon cc src/ -a

# Безопасность
bandit -r src/

# === ЛОКАЛЬНАЯ ПРОВЕРКА ПЕРЕД КОММИТОМ ===

# Установить hook
bash operations/setup_precommit.md

# Проверить как if commit
bash .claude/skills/pre_commit_hook.sh
```

## КРАСНЫЕ ФЛАГИ (что-то не так)

❌ `run_suite.py full` падает или красный (критично)
❌ `generated/health_check_report.md` показывает ошибки (критично)
❌ В src/ есть `except: pass` или `# TODO` без TASK
❌ Есть хардкодированные URL, IP, пароли в коде
❌ Трассируемость разорвана (BR без TASK, TASK без TEST)
❌ AGENTS.md не обновлялся более месяца
❌ Нет pre-commit hook или он не блокирует коммиты
❌ Покрытие тестами < 60%
❌ Есть flaky тесты (нестабильные)
❌ Есть мёртвый код (неиспользуемые модули)
❌ Большой gap между AGENTS.md и реальным кодом
