## Этапы разработки

### m01 — Согласованная и проверяемая основа проекта

- **Статус:** `in-progress`
- **Что это:** подготовка структуры документов, правил и автоматических проверок
- **Когда будет готово:** когда все тесты зелёные + смысловая проверка + подтверждение владельца
- **Ваша роль:** подтвердить состав V1, выбрать принять или вернуть

**Прогресс шагов:**
- [x] Подготовить структуру документов, правила и автоматические проверки основы
- [ ] Подтвердить успешную серверную проверку опубликованной редакции
- [ ] Провести независимую смысловую проверку этой же редакции
- [ ] Получить подтверждение владельца по составу V1
- [ ] Показать выбор: принять `m01` или вернуть его на доработку

## Автоматические проверки

- ✅ Структура документов (документы корректны)
- ✅ Трассировка требований (связи целостны)
- ✅ Версионирование (метаданные верны)
- ✅ Производные представления (могут пересчитаны)
- ⏳ Смысловая проверка (ждёт этапа m01)

## GitHub Actions

Статус серверной проверки не хранится в этом документе, потому что он быстро устаревает. Перед смысловой проверкой агент обязан получить результат GitHub Actions для точного проверяемого SHA и сверить evidence artifact. Пока это не выполнено, серверная готовность считается неподтверждённой.

## Оставшиеся ворота

До принятия `m01` остаются три обязательных ворот:
1. Серверная проверка на GitHub
2. Смысловая проверка документов
3. Подтверждение владельца по составу V1
