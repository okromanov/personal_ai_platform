# TASK_016 — Реальный Telegram Bot API для ARC_CMP_001

## 1. Зачем это делаем

Очередь внутри `TelegramChannel` не является Telegram. Эта TASK заменяет эмуляцию на Bot API и сохраняет единый жизненный цикл задачи.

## 2. Результат

Реальный Telegram webhook или polling принимает сообщение владельца, передаёт его в `Channel` и возвращает ответ; токен получается только через `SecretProvider`. Webhook проверяет отдельный secret token на каждом update до доверия полю владельца; polling использует только исходящее long-polling соединение к Bot API и не открывает входной endpoint. При обязательном VPN-профиле канал не стартует без здорового туннеля.

## 3. Где мы сейчас

[`TASK_001`](task_001_arc_001.md) поставила контракт и queue-эмуляцию без подключения к Telegram Bot API.

## 4. Что делать сейчас

### Агенту

1. Выбрать webhook или polling в границах принятой среды и зафиксировать модель подлинности канала
2. Дополнить allowed_paths и реализовать Bot API
3. Связать Telegram-путь с NetworkPolicy и SecretProvider
4. Создать TEST реального канала, включая поддельный update с идентификатором владельца: webhook обязан отклонить его без корректного secret token; для polling проверяется отсутствие входного endpoint

## 5. План выполнения

- [ ] Дополнить allowed_paths реальными путями

- [ ] Реализовать подлинность транспорта: secret token на каждом webhook update либо только исходящий polling

## 6. Состав

Пути Bot API, конфигурации сети и TEST фиксируются после выбора режима. Токен и значения VPN не включаются в репозиторий.

## 7. Проверки и доказательства

Проверяется внешний Telegram-канал, а также отсутствие вызова модели для чужого user_id, активного Kill Switch и потерянного обязательного туннеля. Отдельный отрицательный сценарий отправляет поддельный update с правильным идентификатором владельца: webhook без верного secret token отклоняет его до `OwnerControl`, а polling-вариант доказывает, что входного endpoint для такой подделки нет.

## 8. Готово когда

- ✅ Владелец может отправить сообщение реальному боту
- ✅ Bot API не использует секрет из кода или лога
- ✅ Подлинность канала подтверждена: каждый webhook update проверяет secret token либо выбран исходящий polling без входного endpoint
- ✅ Отрицательные сценарии не вызывают модель
- ✅ TEST и evidence актуальны для точного SHA
