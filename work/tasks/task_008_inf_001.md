### Что такое Docker и нужно ли его устанавливать

Docker — программа, которая упаковывает код в переносимый «контейнер» (по сути — маленькую изолированную виртуальную машину) и умеет его запускать. Файл `dockerfile` в корне репозитория — рецепт этой упаковки, написанный в этой TASK.

Проверьте, установлен ли Docker:

1. Откройте **PowerShell** (Пуск → написать `PowerShell` → Enter).
2. Введите:
   ```powershell
   docker --version
   ```
3. Если видите что-то вроде `Docker version 27.x.x` — Docker установлен, переходите к шагу «Сборка образа» ниже.
4. Если видите ошибку вроде `docker: команда не найдена` / `not recognized` — Docker не установлен. Установите **Docker Desktop для Windows**: https://www.docker.com/products/docker-desktop/ (обычный установщик, next-next-finish). После установки Docker Desktop нужно **запустить** (иконка кита в трее должна быть неподвижной, не анимированной — это значит, что фоновый сервис поднялся; обычно занимает 30–60 секунд после старта Windows или запуска программы вручную).

### Сборка образа

1. Откройте PowerShell.
2. Перейдите в папку репозитория (замените путь на свой, если он другой):
   ```powershell
   cd C:\путь\до\personal_ai_platform
   ```
3. Соберите образ. Обратите внимание на `-f dockerfile` — это обязательно, потому что файл называется строчными буквами `dockerfile`, а не `Dockerfile`, который Docker ищет сам по себе:
   ```powershell
   docker build -f dockerfile -t personal-ai-platform:local .
   ```
4. Дождитесь окончания (обычно 20–60 секунд при первой сборке, дальше — быстрее). В конце должна быть строка вида `writing image sha256:...` и `naming to docker.io/library/personal-ai-platform:local`, без слова `ERROR` где-либо в выводе.

### Проверка работоспособности

5. Запустите собранный образ:
   ```powershell
   docker run --rm personal-ai-platform:local
   ```
6. Ожидаемый результат — ровно одна строка вывода, похожая на:
   ```json
   {"healthy": true, "version": "unknown", "dependencies": []}
   ```
   (`"version": "unknown"` — это нормально: версию образа сюда не передавали. Если хотите, чтобы отображался номер версии, передайте его через `--build-arg APP_VERSION=1.0` на шаге сборки.)
7. Проверьте код завершения — сразу после команды введите:
   ```powershell
   echo $LASTEXITCODE
   ```
   Ожидается `0`. Это и есть то, что должен вернуть Docker `HEALTHCHECK` при работающем контейнере.

### Если что-то пошло не так

Скопируйте весь вывод команды (не только последнюю строку) и пришлите его — конкретная ошибка на шаге 3 (сборка) или на шаге 5–7 (запуск) точно скажет, что чинить в `dockerfile`.
