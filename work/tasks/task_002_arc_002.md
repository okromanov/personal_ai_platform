# TASK_002 — Реализация ARC_CMP_002

## 1. Зачем это делаем

Реализовать хранилище задач (Task Storage) - центральное хранилище всех задач и их состояний. Это критично для работы всей системы: без него задачи теряются, невозможно отслеживать прогресс и нельзя восстановиться после сбоя. Компонент должен надёжно сохранять и загружать задачи, поддерживать запросы по статусу и фильтрацию.

## 2. Результат

Стабильный интерфейс `TaskStorage` и минимальная рабочая реализация (в памяти или с простой файловой БД). Компонент принимает `TaskMessage`, сохраняет, загружает по ID, поддерживает поиск по статусу. Тест `TEST_008` проверяет все операции: создание, загрузку, обновление состояния, фильтрацию. После завершения - готовно к интеграции с остальными компонентами (scheduler, executor).

## 3. Где мы сейчас

Спецификация есть, реализации нет. Компонент полностью зависит от TASK_001 (каналы готовы). `allowed_paths` намеренно узкий - агент сам определит где реализовывать и явно добавит пути до начала работы (не догадка, а факт).
