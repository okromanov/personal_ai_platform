# TASK_012 — Реализация INF_CMP_007

## 1. Зачем это делаем

Реализовать сбор сведений о работоспособности, ошибках, ресурсах, стоимости и технических событиях без лишнего копирования чувствительного содержимого. Без наблюдаемости эксплуатационные функции ([`TASK_007`](task_007_arc_009.md)) не имеют данных, на основе которых принимать решения о работоспособности системы, а инциденты обнаруживаются только постфактум пользователями.

## 2. Результат

Механизм сбора технических наблюдений для сервисов платформы, дающий эксплуатационным функциям ([`TASK_007`](task_007_arc_009.md)) данные для оценки работоспособности. Он явно исключает чувствительное содержимое пользовательских задач: собираются технические сведения, а не пользовательские данные.

## 3. Где мы сейчас

Спецификация [`INF_CMP_007`](../../specifications/infrastructure_baseline.md#inf_cmp_007) определяет требования ([`INF_REQ_012`](../../specifications/infrastructure_baseline.md#inf_req_012), [`INF_REQ_013`](../../specifications/infrastructure_baseline.md#inf_req_013)). Реализация использует переносимое SQLite-хранилище, продолжая подход постоянного локального состояния из [`TASK_011`](task_011_inf_005.md), без отдельного сетевого сервиса.

## 6. Состав

Сборщик наблюдений будет принимать отчёт HealthReport, измерения ресурсов, счётчики внешнего потребления и числовые технические события. В запись попадут только технический идентификатор, время и числа/логические значения; свободный текст, секреты, пользовательские идентификаторы, задачи и ответы не будут иметь поля хранения и должны отклоняться валидацией.

SQLite-хранилище сохранит эти записи в переносимой локальной базе. Это минимально достаточная реализация для [`m02`](../../milestones.md#m02): она переживает перезапуск, не требует сетевого сервиса и может быть заменена малым контрактом без изменения сборщика.
