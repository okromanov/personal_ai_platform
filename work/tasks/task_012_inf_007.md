# TASK_012 — Реализация INF_CMP_007

## 1. Зачем это делаем

Реализовать сбор сведений о работоспособности, ошибках, ресурсах, стоимости и технических событиях без лишнего копирования чувствительного содержимого. Без наблюдаемости эксплуатационные функции ([`TASK_007`](task_007_arc_009.md)) не имеют данных, на основе которых принимать решения о работоспособности системы, а инциденты обнаруживаются только постфактум пользователями.

## 2. Результат

Механизм сбора логов, метрик и событий для сервисов платформы, дающий эксплуатационным функциям ([`TASK_007`](task_007_arc_009.md)) данные для оценки работоспособности. Явно исключает чувствительное содержимое пользовательских задач — собираются технические сведения, а не пользовательские данные.

## 3. Где мы сейчас

Спецификация [`INF_CMP_007`](../../specifications/infrastructure_baseline.md#inf_cmp_007) определяет требования ([`INF_REQ_012`](../../specifications/infrastructure_baseline.md#inf_req_012), [`INF_REQ_013`](../../specifications/infrastructure_baseline.md#inf_req_013)). Реализации нет. Зависит от [`TASK_011`](task_011_inf_005.md) (постоянное хранилище) — метрики и события сами нуждаются в постоянном хранении для последующего анализа.
