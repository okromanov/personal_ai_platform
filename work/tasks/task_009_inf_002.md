# TASK_009 — Реализация INF_CMP_002

## 1. Зачем это делаем

Определить сетевые маршруты, правила входящего и исходящего трафика, DNS и, при необходимости, защищённые туннели для явно назначенных адресов. Без контролируемого исходящего трафика вычислительная среда (`TASK_008`) может обращаться к произвольным внешним адресам — это прямой риск для шлюза инструментов (`TASK_005`), который должен быть единственной точкой авторизации внешних вызовов.

## 2. Результат

Задокументированные и, где возможно, автоматизированные сетевые правила: список разрешённых исходящих адресов (allowlist), правила входящего трафика для сервисов платформы, DNS-конфигурация. Согласовано с моделью авторизации `ToolGateway` (`TASK_005`) — сетевые ограничения дополняют, а не заменяют проверку на уровне приложения.

## 3. Где мы сейчас

Спецификация [`INF_CMP_002`](../../specifications/infrastructure_baseline.md#inf_cmp_002) определяет требования (`INF_REQ_003`, `INF_REQ_004`, `INF_REQ_005`). Реализации нет. Зависит от `TASK_008` (вычислительная среда) — сетевые правила применяются к уже определённой среде выполнения.
