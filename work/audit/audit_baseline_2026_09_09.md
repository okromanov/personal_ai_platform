## 2. Итог

**Readiness: NOT READY.** Подтверждены существенное нарушение авторизации/валидации данных (AUD-041) и неполнота блокирующего AST-детектора (AUD-042); оба остаются открытыми. Главный риск: `frozen=True` не делает вложенный словарь неизменяемым. Вызывающий код может изменить проверенные параметры, а поздний потребитель прочитает новое значение. Воспроизведены два проявления одной причины: обработчик инструмента потребляет неавторизованное значение параметра, а SQLite принимает свободный текст в числовую телеметрию. Реальный внешний эффект и утечка реальных данных не демонстрировались.

## 4. Карточки findings

<a id="aud-041"></a>
### AUD-041 — Изменяемый payload переживает проверку

- **Severity/Confidence/Evidence state:** HIGH / HIGH / CONFIRMED.
- **Baseline:** pre-existing на проверяемом SHA; момент появления и регрессия не установлены.
- **Файл:** [`ToolCall.params`](../../src/tools/base.py), [`ToolGatewayImpl.call`](../../src/tools/registry.py), [`ObservationEvent.__post_init__`](../../src/observability/collector.py), [`SQLiteObservabilityStore.append`](../../src/observability/sqlite_store.py).
- **Ожидаемый контракт:** SYS_020, SEC_CTL_007/008 связывают разрешение с точными параметрами; TASK_012 и SEC_CTL_014 ограничивают телеметрию техническими данными. `ObservationEvent` явно допускает только числа/bool.
- **Наблюдаемое поведение:** frozen dataclass хранит изменяемый словарь вызывающей стороны. Авторизация/валидация видит одно содержимое, а последующее исполнение/хранение — другое.
- **Наблюдаемое поведение:** первый неподтверждённый вызов отклонён; подтверждённый авторизован для `APPROVED`. Пока async-обработчик ждёт, исходный словарь изменён. Обработчик прочитал `NOT_APPROVED`, gateway вернул `succeeded=True`.
- **Наблюдаемое поведение:** событие создано с `count=1`; после проверки исходный Mapping изменён на синтетическую строку. `append` не отклонил запись; прямой SELECT вернул эту строку из SQLite.
- **Воздействие и достижимость:** публичные API компонентов, сохранённая ссылка на словарь и, для инструмента, async-ожидание до чтения параметров. Злонамеренный обработчик не требуется. Достижимость из production Telegram/model входа и реальный внешний эффект не доказаны; поэтому не заявлена внешняя компрометация уровня CRITICAL.
- **Почему предыдущий аудит пропустил:** два проявления объединены по одной причине. AUD-024/029 касались отсутствовавшего runtime-event контракта и согласованности ADR/TASK, а не изменения данных после проверки.
- **Рекомендованное исправление:** до проверки получить независимый снимок payload и исполнять именно авторизованный снимок. Для вложенных JSON-параметров поверхностной копии недостаточно. Измерения события отделить от исходного Mapping; проверять набор, реально передаваемый на запись.
- **Как проверить исправление:** приведённые отрицательные сценарии больше не нарушают контракты; неизменённые значения проходят. Добавлены nested-mutation и async-interleaving тесты; полный gate и CI проходят на SHA исправления.

Воспроизведение в отдельной копии проверяемого SHA (внешних действий нет):

```python
import asyncio
import sqlite3
import tempfile
from dataclasses import replace
from pathlib import Path
from src.owner_control import ActionClass, OwnerControlGate
from src.tools import Capability, ToolCall, ToolGatewayImpl
from src.observability import ObservationEvent, ObservationKind, SQLiteObservabilityStore

async def probe():
    with tempfile.TemporaryDirectory() as tmp:
        started, resume = asyncio.Event(), asyncio.Event()
        seen = []
        async def handler(call):
            started.set()
            await resume.wait()
            seen.append(call.params['subject'])
            return 'synthetic effect only'
        gateway = ToolGatewayImpl(OwnerControlGate('owner', Path(tmp)), [Capability(
            name='send', effect_class=ActionClass.WRITE_EXTERNAL,
            handler=handler, allowed_subjects=frozenset({'owner'}),
            allowed_resources=frozenset({'synthetic_resource'}),
            allowed_param_names=frozenset({'subject'}),
        )])
        call = ToolCall('audit_action', 'owner', 'send', 'synthetic_resource',
                        params={'subject': 'APPROVED'})
        assert not (await gateway.call(call)).succeeded
        task = asyncio.create_task(gateway.call(replace(call, confirmed=True)))
        await asyncio.wait_for(started.wait(), 2)
        call.params['subject'] = 'NOT_APPROVED'
        resume.set()
        result = await asyncio.wait_for(task, 2)
        print('tool:', result.succeeded, seen)
    with tempfile.TemporaryDirectory() as tmp:
        db = Path(tmp) / 'observations.sqlite3'
        store = SQLiteObservabilityStore(db)
        values = {'count': 1}
        event = ObservationEvent(ObservationKind.TECHNICAL_EVENT, 'audit', values)
        values['count'] = 'SYNTHETIC_PRIVATE_TEXT'
        store.append(event)
        with sqlite3.connect(db) as conn:
            print('stored:', conn.execute(
                'SELECT measurements_json FROM observation_events').fetchall())

asyncio.run(probe())
```

У уязвимой редакции вывод содержит `tool: True ['NOT_APPROVED']` и строку `SYNTHETIC_PRIVATE_TEXT` в `stored`. Контроль: убрать только две строки изменения словарей — обработчик получает `APPROVED`, база хранит число `1`.

<a id="aud-042"></a>
### AUD-042 — AST gate пропускает документированные заглушки

- **Severity/Confidence/Evidence state:** MEDIUM / HIGH / CONFIRMED.
- **Baseline:** pre-existing; совпадающей причины в AUD-001–040 не найдено.
- **Файл:** [`code_analyzer.py`](../../operations/scripts/quality/code_analyzer.py), `StubDetector._check_function` и `main`; [`test_code_analyzer.py`](../../operations/tests/tooling/test_code_analyzer.py).
- **Ожидаемый контракт:** блокирующий шаг полного gate отклоняет неготовые функции, реализованные только `pass` или `raise NotImplementedError`.
- **Наблюдаемое поведение:** `len(node.body) == 1` не учитывает docstring как отдельный AST statement. Кроме того, детектор проверяет только `ast.Call`, пропуская `raise NotImplementedError` как `ast.Name`.
- **Как воспроизвести:** в временном дереве с каноническими каталогами `src`, `operations/scripts`, `operations/tests` запускался настоящий `main()`. Голый `pass` дал exit 1; docstring + `pass`, голый `raise NotImplementedError` и docstring + `raise NotImplementedError()` дали exit 0; реальная функция с `return 42` дала exit 0. Ошибки загрузки не использовались как доказательство.
- **Воздействие и достижимость:** обещание AST gate неполно; обычное документирование делает ту же заглушку невидимой. Это не доказательство отсутствия остальных тестов или обхода всего CI.
- **Рекомендованное исправление:** убрать только начальный docstring из анализируемого тела, обработать оба корректных синтаксиса raise; сохранить явную политику для абстрактных интерфейсов.
- **Как проверить исправление:** CLI отклоняет все перечисленные формы обычной неготовой функции, но принимает реализованную функцию; тесты проверяют exit code, а не только наличие класса детектора.

Минимальная локализация дефекта:

```python
import ast
from operations.scripts.quality.code_analyzer import StubDetector
for source in (
    'def f():\n    pass\n',
    'def f():\n    """Pending implementation."""\n    pass\n',
    'def f():\n    raise NotImplementedError\n',
):
    detector = StubDetector('synthetic.py')
    detector.visit(ast.parse(source))
    print(len(detector.stubs))
```

Наблюдаемый вывод: `1`, `0`, `0`. Полный CLI подтвердил соответствующие коды `1`, `0`, `0`.
