# Шаблон этапа

## Обязательная декомпозиция пользовательского результата

После раздела «Подэтапы» каждый новый этап обязан содержать раздел
«Очередь, закрывающая пользовательский результат». В нём для каждого
наблюдаемого результата из строки `результат` указываются terminal TASK и
вид обязательного доказательства. Если результат требует внешний канал,
поставщика, сеть, постоянно работающую среду или действие владельца,
terminal TASK и TEST должны проверять именно этот внешний контур; контракт,
stub и unit-тест не заменяют его.

Эта матрица создаётся при планировании этапа. Каждый `proposed` ADR из строки
«ADR этого этапа» немедленно назначается ровно одной незавершённой TASK через
`decides`, включая `planned` milestones. Перед принятием этапа независимый
аудит сверяет обе матрицы построчно с реализацией, решением владельца и
evidence.

Все требуемые поля frontmatter должны соответствовать стандарту, описанному в [`operations/change_process.md#82`](../change_process.md).

```markdown
## mXX — <Наблюдаемый результат>

- work_state: `planned`
- результат: <что изменится для владельца/проекта>
- состав: <точные идентификаторы BR/SYS/SEC/INF/ADR>
- ADR этого этапа: <ADR_XXX или нет>
- карта решений: <ADR_XXX → TASK_XXX для каждого proposed ADR>
- правило: до выхода из `planned` состав должен быть выражен точными устойчивыми идентификаторами; маски, `applicable *` и ссылки на неименованный общий состав запрещены.
- обязательные доказательства: <TEST и виды доказательств>

### Подэтапы
1. Выбрать ближайшие BR и при необходимости детализировать их до проверяемого состава SYS/THR/SEC/ARC/INF.
2. До основной реализации зафиксировать окончательный состав, профиль качества и TASK-владельца каждого proposed ADR.
3. Выполнить минимальные подэтапы реализации.
4. Получить обязательные доказательства и проверить полное покрытие состава.
```

Этап определяет время и состав, но не дублирует тексты требований или архитектурных инвариантов. Планируемый этап может начинаться с чернового состава на уровне бизнес-потребностей. Реализация не начинается, пока не готовы обязательный проверяемый состав и профиль качества.
