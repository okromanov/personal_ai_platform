# Жизненный цикл скиллов

## 1. Статус

Это предложение, а не действующая часть поставки. Оно применяется только после отдельного бизнес-требования, регистрации типа Skill и активной TASK.

Общая последовательность состояний, переходы и правила отката определены в [`state_machines.md`](state_machines.md). Здесь описаны только риски и доказательства, специфичные для Skill.

## 2. Объект

Skill — версионируемый пакет инструкций и ресурсов, который расширяет способ выполнения задачи, но не получает полномочия сам по себе. Полномочия остаются у вызывающего агента и подключённых Tool.

Минимальная запись кандидата содержит:

- стабильный идентификатор и версию;
- назначение и границы применимости;
- владельца и источник пакета;
- требуемые Tool и данные;
- набор eval-кейсов и критерии удаления.

## 3. Риски

- инструкции пакета конфликтуют с authority-документами;
- недоверенный ресурс пытается расширить полномочия;
- новая версия меняет поведение без повторной проверки;
- выбор Skill становится неявным и невоспроизводимым;
- удалённый Skill остаётся в маршрутизации или кэше.

## 4. Проверки по фазам

### Candidate

Проверяются происхождение, лицензия, состав файлов, отсутствие секретов и заявленные зависимости. Неизвестный источник блокирует переход.

### In review

Проводятся статический анализ инструкций, threat review и eval на положительных, отрицательных и конфликтных запросах. Проверяется, что Skill не обходит owner control и не подменяет источники истины.

### Hardening

Фиксируются версия и хэш, ограничиваются ресурсы и Tool, добавляются негативные тесты на prompt injection, утечку данных и неверную маршрутизацию.

### Probation

Skill включается только для ограниченного профиля. Наблюдаются ошибки выбора, откаты, обращения к Tool и качество результата.

### Accepted

Разрешена только проверенная версия. Обновление создаёт нового кандидата и не меняет принятую версию на месте.

### Retired

Skill удаляется из маршрутизации; кэш и ссылки проверяются на отсутствие активного использования. Возврат возможен только через новый цикл.

## 5. Доказательства

Для принятия нужны:

- хэш пакета и источник;
- результаты eval на точном Git SHA;
- перечень доступных Tool и данных;
- результат security review;
- наблюдения probation и критерий отката.

Документ или запись в реестре без исполняемой проверки не является доказательством.

## 6. Отказ и отзыв

До принятия кандидат может перейти в `rejected` с причиной. После принятия обнаруженный критический риск переводит его в `retired`, отключает маршрутизацию и создаёт новый кандидат только после устранения причины.
