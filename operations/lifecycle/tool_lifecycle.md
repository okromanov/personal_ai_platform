# Жизненный цикл инструментов

## 1. Статус

Это предложение, а не действующая часть поставки. Оно применяется после отдельного бизнес-требования, регистрации типа Tool и активной TASK.

Общие состояния и переходы определены в [`state_machines.md`](state_machines.md). Этот документ добавляет только проверки полномочий и внешних эффектов Tool.

## 2. Объект

Tool — вызываемая возможность с явным входным контрактом, классом воздействия и границей авторизации. Описание Tool не даёт ему полномочий: фактический вызов проходит через owner control и policy.

Минимальная запись кандидата содержит:

- стабильный идентификатор, версию и владельца;
- схему входа и выхода;
- класс воздействия: чтение, внешняя запись, разрушительное или административное действие;
- требуемые credentials, сети и данные;
- таймаут, идемпотентность, компенсацию и критерий отзыва.

## 3. Риски

- schema или метаданные скрывают реальный внешний эффект;
- credentials шире минимально необходимых;
- повтор создаёт второй необратимый эффект;
- результат Tool принимается как доверенная инструкция;
- отказ оставляет частичное внешнее состояние;
- retired-версия остаётся доступной через реестр или кэш.

## 4. Проверки по фазам

### Candidate

Проверяются происхождение, лицензия, схема, зависимости, сетевые направления и секреты. Класс воздействия устанавливается по факту реализации.

### In review

Проводятся threat review, проверка authorisation-before-execution, негативные тесты схемы и моделирование отказов.

### Hardening

Ограничиваются credentials и egress, добавляются таймауты, идемпотентность либо компенсация, редактирование чувствительных логов и fail-closed поведение.

### Probation

Доступ ограничен выбранным профилем. Наблюдаются отказы, повторные эффекты, запросы разрешений и откаты.

### Accepted

Разрешена конкретная проверенная версия с минимальными полномочиями. Изменение схемы, эффекта, credentials или сети создаёт нового кандидата.

### Retired

Tool удаляется из реестра вызовов, credentials отзываются, активные операции завершаются безопасно. Возврат проходит полный цикл заново.

## 5. Доказательства

Для принятия нужны:

- хэш реализации и схема;
- матрица эффекта, полномочий, credentials и egress;
- автоматические тесты разрешения и отказа;
- результаты fault injection для таймаута, повтора и частичного сбоя;
- журнал probation без неразрешённых внешних эффектов.

Зелёный unit-тест без проверки фактической границы авторизации не подтверждает безопасность Tool.

## 6. Немедленный отзыв

Утечка секрета, обход owner control, неверно классифицированный эффект или неконтролируемый повтор требуют немедленного перехода принятой версии в `retired`, отзыва credentials и фиксации инцидента. Исправление выпускается как новый кандидат.
