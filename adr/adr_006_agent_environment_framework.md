# ADR_006 — Выбор среды выполнения агента

## 1. Назначение

Зафиксировать Claude Agent SDK как кандидата для сравнительной проверки среды выполнения агента в m02, сохраняя заменяемую границу `RuntimePort` по [`SYS_003`](../specifications/system_specification.md#sys_003).

## 2. Контекст

ADR_002 определяет границу `RuntimePort` между средой и платформой. Конкретный фреймворк выбирается в [`m02`](../milestones.md#m02) после проверки кандидатов для первого сквозного сценария ([`BR_001`](../specifications/business_requirements.md#br_001), [`SYS_001`](../specifications/system_specification.md#sys_001), [`SYS_003`](../specifications/system_specification.md#sys_003)):

- среда должна выполнять управляемый цикл обычной задачи через [`ARC_CMP_003`](../specifications/architecture_baseline.md#arc_cmp_003);
- особенности SDK не должны проникать в канал [`ARC_CMP_001`](../specifications/architecture_baseline.md#arc_cmp_001) и контракты платформы;
- смена кандидата не должна менять пользовательский сценарий или каноническое состояние;
- расширенные память, инструменты и автономность оцениваются как будущая пригодность, но не расширяют состав [`m02`](../milestones.md#m02).

## 3. Предлагаемое решение

Включить **Claude Agent SDK** в сравнение 2–3 сред и реализовать с ним один минимальный прототип:

1. **Управление памятью:** Встроенная поддержка контекстных окон и управление историей
2. **Инструменты:** Типизированный контракт инструментов с явными границами
3. **Цикл:** Управляемый цикл с явной передачей управления (не скрытая автоматизация)
4. **Безопасность:** Изоляция инструментов через отдельные экземпляры и контексты
5. **Эволюция:** `RuntimePort` позволяет сравнивать и заменять среды без изменения ядра.

Документ остаётся `proposed` до сравнительного evidence и решения владельца. Он не разрешает заранее использовать Claude Agent SDK во всех этапах m02–m06.

## 4. Альтернативы

| Вариант | Преимущества | Недостатки |
|---------|-------------|-----------|
| **Claude Agent SDK (кандидат)** | Явное управление циклом, качество планирования | Проприетарный, зависит от Anthropic |
| LangChain | Популярность, поддержка много поставщиков | "Магия" в фреймворке, сложнее контроль |
| AutoGen | Многоагентные архитектуры | Излишняя сложность для одного агента |
| Собственный цикл | Максимальный контроль | Огромные затраты, воспроизведение известных проблем |

## 5. Последствия

**Положительные:**
- Явное управление шагами агента (для SEC_CTL)
- Встроенная поддержка долгого контекста
- Качественное планирование и reasoning
- `RuntimePort` остаётся фреймворк-агностичным

**Отрицательные:**
- Привязка к Claude SDK (в рамках `RuntimePort`)
- Нужно изучить специфику этой среды
- Некоторые фичи может потребовать адаптация позже

## 6. Проверка

- [ ] Claude Agent SDK и минимум один альтернативный runtime проверены на одном сценарии.
- [ ] `RuntimePort` не содержит импортов конкретного SDK.
- [ ] Каждый прототип выполняет цикл план → инструмент → проверка → следующий шаг.
- [ ] Проверены отмена, изоляция инструментов и явное управление состоянием.
- [ ] Evidence и решение владельца зафиксированы до смены `decision_state`.
