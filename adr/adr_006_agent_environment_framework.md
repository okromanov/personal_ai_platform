# ADR_006 — Выбор среды выполнения агента

## 1. Назначение

Зафиксировать набор из шести кандидатов среды выполнения агента для сравнения в [`m02`](../milestones.md#m02), согласованный с владельцем: LangGraph, CrewAI, Hermes Agent, OpenHands, Pi coding agent и собственная минимальная реализация без внешнего фреймворка. Ни один вариант не предпочтён этим документом. Граница `RuntimePort` по [`SYS_003`](../specifications/system_specification.md#sys_003) остаётся заменяемой независимо от исхода сравнения; явное требование владельца — инвариантность среды к выбору модели — действует как жёсткий отсекающий критерий (см. §2), а не как предпочтение.

## 2. Контекст

[`ADR_002`](adr_002_core_runtime_boundary.md#adr_002) определяет границу `RuntimePort` между средой и платформой. Конкретный фреймворк выбирается в [`m02`](../milestones.md#m02) после проверки кандидатов для первого сквозного сценария ([`BR_001`](../specifications/business_requirements.md#br_001), [`SYS_001`](../specifications/system_specification.md#sys_001), [`SYS_003`](../specifications/system_specification.md#sys_003)):

- среда должна выполнять управляемый цикл обычной задачи через [`ARC_CMP_003`](../specifications/architecture_baseline.md#arc_cmp_003);
- особенности SDK не должны проникать в канал [`ARC_CMP_001`](../specifications/architecture_baseline.md#arc_cmp_001) и контракты платформы;
- смена кандидата не должна менять пользовательский сценарий или каноническое состояние;
- расширенные память, инструменты и автономность оцениваются как будущая пригодность, но не расширяют состав [`m02`](../milestones.md#m02).

**Явное требование владельца:** среда выполнения агента должна быть инвариантна к выбору модели ([`BR_033`](../specifications/business_requirements.md#br_033)) — не только заменяема через `RuntimePort` снаружи, но и не завязана на конкретного поставщика модели *внутри* собственного цикла рассуждения. Это отсекающий критерий, а не предпочтение: он исключает Claude Agent SDK из сравнения ещё до scorecard, потому что его цикл рассуждения и tool-use жёстко вызывает Anthropic API изнутри самого SDK, независимо от того, что подключено через `ModelGateway` — смена модели потребовала бы смены самой среды, а не конфигурации.

**Многоагентная пригодность (оценочный критерий, добавлен 2026-09-01).** Владелец зафиксировал направление на многоагентное выполнение: несколько ролей работают над одной задачей, роль развивается по накопленному опыту с обязательным подтверждением владельца, агент может запускать субагента с профилем полномочий его собственной роли, а взаимодействие и развитие ролей наблюдаемы. Решения владельца и открытые вопросы собраны в [`agent_roles_and_delegation.md`](../operations/architecture/agent_roles_and_delegation.md).

Это направление **не входит в состав V1** и не имеет `BR_*`: его требования формулируются на [`m07`](../milestones.md#m07). Но среда выбирается сейчас, в [`m02`](../milestones.md#m02), и переживёт V1, поэтому многоагентная пригодность оценивается уже в этом сравнении — не как отсекающий критерий (она не исключает ни одного из шести кандидатов), а как обязательный раздел evidence по каждому кандидату, чтобы среда не была выбрана вслепую относительно уже известной цели. По каждому кандидату фиксируется:

- есть ли роли и передача работы между ними как явная конструкция среды, или это пришлось бы строить поверх неё;
- может ли шаг цикла запустить подчинённый цикл (субагент) с *собственным*, а не унаследованным набором полномочий — и остаётся ли цепочка запусков видимой платформе, а не только внутренней для среды: без этих данных ни разрешённый граф делегирования, ни контроль на действии (см. §2.4 черновика) не проверяемы;
- выносит ли среда наружу события «кто взял часть работы, кому передал, чем закончилось» в форме, пригодной для [`ARC_CMP_009`](../specifications/architecture_baseline.md#arc_cmp_009), или держит их во внутреннем состоянии;
- чего будет стоить отказ от многоагентности этой среды, если на [`m07`](../milestones.md#m07) окажется дешевле построить её поверх `RuntimePort` самостоятельно.

## 3. Предлагаемое решение

Сравнить в [`m02`](../milestones.md#m02) шесть кандидатов, каждый способный по конструкции пройти критерий модель-инвариантности из §2, и реализовать с каждым один минимальный прототип:

1. **LangGraph (кандидат)** — граф-ориентированный, явно управляемый цикл поверх LangChain.
2. **CrewAI (кандидат)** — ролевая многоагентная оркестрация поверх модель-агностичного слоя вызовов.
3. **Hermes Agent (кандидат)** — готовая агентная среда, запрошенная владельцем к сравнению; требует отдельной проверки на модель-инвариантность, прозрачность состояния и отсутствие обхода `OwnerControl`, поскольку это менее известный инструмент, чем LangGraph/CrewAI.
4. **OpenHands (кандидат)** — открытый рантайм автономного coding-агента с песочницей выполнения и tool-loop; заявлен как модель-агностичный (конфигурация провайдера снаружи цикла), но это требует отдельного доказательства на прототипе, а не принимается по заявлению проекта.
5. **Pi coding agent (кандидат)** — минималистичный агентный CLI-харнесс (`pi-agent-core` + `pi-ai`) с явным акцентом на token-efficiency; имеет собственный встроенный унифицированный LLM API (`pi-ai`), который при выборе этого кандидата не используется — вызовы модели идут через `ModelGateway`, поэтому отдельно проверяется, что `pi-agent-core` действительно позволяет подменить встроенный `pi-ai` без потери цикла план → инструмент → проверка.
6. **Собственная минимальная реализация без внешнего фреймворка (кандидат)** — явный цикл план → инструмент → проверка, написанный поверх `ModelGateway` без промежуточного фреймворка.

Общее для всех кандидатов:
- **Управление памятью:** явное состояние (не скрытая история); управление контекстом остаётся на стороне платформы.
- **Инструменты:** типизированный контракт инструментов с явными границами, независимый от того, какая модель их вызывает.
- **Цикл:** управляемая последовательность шагов с явной передачей управления (не скрытая автоматизация), без скрытого обхода платформенных проверок.
- **Модель-инвариантность:** узел/шаг, вызывающий модель, обращается к ней через `ModelGateway` ([`ADR_003`](adr_003_model_provider_interface.md#adr_003)) — смена модели или её поставщика не требует смены цикла.
- **Безопасность:** изоляция инструментов через явные границы состояния.
- **Эволюция:** `RuntimePort` позволяет сравнивать и заменять среды без изменения ядра.

Документ остаётся `proposed` до сравнительного evidence и решения владельца. Он не разрешает заранее использовать ни один из шести кандидатов во всех этапах [`m02`](../milestones.md#m02)–[`m06`](../milestones.md#m06).

## 4. Альтернативы

| Вариант | Преимущества | Недостатки |
|---------|-------------|-----------|
| **LangGraph (кандидат)** | Явный граф состояний, модель-инвариантен по конструкции, зрелая экосистема адаптеров моделей | Больше начальной сложности настройки, чем у монолитного SDK |
| **CrewAI (кандидат)** | Ролевая модель агентов может упростить описание многошаговых сценариев, модель-агностичный слой вызовов | Меньше явного контроля над передачей управления между шагами, чем в LangGraph |
| **Hermes Agent (кандидат)** | Готовая агентная среда, запрошенная владельцем к сравнению | Менее известный инструмент, чем LangGraph/CrewAI — модель-инвариантность, прозрачность состояния и отсутствие обхода `OwnerControl` нужно доказать отдельно, а не предполагать по аналогии |
| **OpenHands (кандидат)** | Готовая песочница выполнения и tool-loop для coding-агента, активное сообщество | Заточен под автономные software-engineering сценарии — нужно отдельно проверить, что цикл не тянет за собой лишние допущения (например, о постоянном доступе к репозиторию/shell) за пределы разрешённой `ModelGateway`/`OwnerControl` границы |
| **Pi coding agent (кандидат)** | Минимальный, token-efficient, простой для аудита код агентного цикла | Молодой проект с менее зрелой экосистемой, чем LangGraph/CrewAI; собственный `pi-ai` нужно суметь отключить в пользу `ModelGateway`, не сломав цикл |
| **Собственная минимальная реализация (кандидат)** | Максимальный контроль, минимум внешних зависимостей, полная и очевидная модель-инвариантность | Нужно самостоятельно реализовать то, что фреймворки уже решили (память, инструменты, ветвление) |
| LangChain (без LangGraph) | Тот же модель-агностичный слой моделей, проще для линейных сценариев | Менее явное управление ветвлением цикла, чем в LangGraph |
| Claude Agent SDK | Явное управление циклом, качество планирования | Не инвариантен к модели: цикл жёстко вызывает Anthropic API изнутри — не проходит отсекающий критерий владельца (§2), в сравнение не включён |
| AutoGen | Многоагентные архитектуры | Прежнее основание отклонения («нет явной потребности в нескольких ролях») перестало быть верным: потребность зафиксирована в [`agent_roles_and_delegation.md`](../operations/architecture/agent_roles_and_delegation.md). Остаётся вне сравнения по другой причине: состав V1 многоагентность не содержит, а вводить ради неё седьмого кандидата в идущее сравнение [`m02`](../milestones.md#m02) — расширение объёма этапа. Подлежит пересмотру на [`m07`](../milestones.md#m07) вместе с самим направлением |

## 5. Последствия

**Положительные:**
- Явное управление шагами агента (для SEC_CTL)
- Шесть реально сравнимых кандидатов, каждый по конструкции способен пройти критерий модель-инвариантности
- `RuntimePort` остаётся фреймворк-агностичным независимо от исхода

**Отрицательные:**
- Сравнение шести кандидатов и по два прототипа с разными моделями для каждого — больше evidence-работы, чем сравнение одного варианта
- Hermes Agent, OpenHands и Pi coding agent требуют отдельного доказательства модель-инвариантности (и для Hermes Agent — дополнительно отсутствия обхода `OwnerControl`), поскольку это менее изученные для проекта инструменты, чем LangGraph/CrewAI
- Собственная реализация (если выберут её) переносит на проект риски и трудозатраты, которые фреймворк уже решил бы
- Часть "магии" абстракций LangGraph/CrewAI/Hermes Agent/OpenHands/Pi требует внимательной проверки на скрытые побочные вызовы

## 6. Проверка

- [ ] Все шесть кандидатов (LangGraph, CrewAI, Hermes Agent, OpenHands, Pi coding agent, собственная реализация) проверены на одном сценарии.
- [ ] `RuntimePort` не содержит импортов конкретного SDK.
- [ ] Для каждого кандидата прототип проходит цикл план → инструмент → проверка → следующий шаг с двумя разными поставщиками модели без изменения графа/цикла — это и есть доказательство модель-инвариантности, а не только заявление.
- [ ] Для Hermes Agent и OpenHands отдельно подтверждено отсутствие обхода `OwnerControl`.
- [ ] Для Pi coding agent подтверждено, что встроенный `pi-ai` можно отключить в пользу `ModelGateway` без потери цикла `pi-agent-core`.
- [ ] Проверены отмена, изоляция инструментов и явное управление состоянием для каждого кандидата.
- [ ] Evidence и решение владельца зафиксированы до смены `decision_state`.
