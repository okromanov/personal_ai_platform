# ADR_006 — Выбор среды выполнения агента

## 1. Назначение

Зафиксировать **LangGraph**, **Hermes Agent** и минимальный **native loop** как три кандидата для сравнительной проверки среды выполнения агента в [`m02`](../milestones.md#m02), сохраняя заменяемую границу `RuntimePort` по [`SYS_003`](../specifications/system_specification.md#sys_003) и явное требование владельца — инвариантность среды к выбору модели.

## 2. Контекст

[`ADR_002`](adr_002_core_runtime_boundary.md#adr_002) определяет границу `RuntimePort` между средой и платформой. Конкретный фреймворк выбирается в [`m02`](../milestones.md#m02) после проверки кандидатов для первого сквозного сценария ([`BR_001`](../specifications/business_requirements.md#br_001), [`SYS_001`](../specifications/system_specification.md#sys_001), [`SYS_003`](../specifications/system_specification.md#sys_003)):

- среда должна выполнять управляемый цикл обычной задачи через [`ARC_CMP_003`](../specifications/architecture_baseline.md#arc_cmp_003);
- особенности SDK не должны проникать в канал [`ARC_CMP_001`](../specifications/architecture_baseline.md#arc_cmp_001) и контракты платформы;
- смена кандидата не должна менять пользовательский сценарий или каноническое состояние;
- расширенные память, инструменты и автономность оцениваются как будущая пригодность, но не расширяют состав [`m02`](../milestones.md#m02).

**Явное требование владельца:** среда выполнения агента должна быть инвариантна к выбору модели ([`BR_033`](../specifications/business_requirements.md#br_033)) — не только заменяема через `RuntimePort` снаружи, но и не завязана на конкретного поставщика модели *внутри* собственного цикла рассуждения. Это исключает Claude Agent SDK как первого кандидата: его цикл рассуждения и tool-use жёстко вызывает Anthropic API изнутри самого SDK, независимо от того, что подключено через `ModelProvider` — смена модели потребовала бы смены самой среды, а не конфигурации, что прямо противоречит требованию.

## 3. Предлагаемое решение

Сравнить три среды на одном минимальном сценарии и реализовать для каждой сопоставимый прототип:

1. **LangGraph** — граф-ориентированный, явно управляемый цикл поверх LangChain.
2. **Hermes Agent** — готовая агентная среда, которую нужно проверить на модель-инвариантность, прозрачность состояния и возможность сохранить контроль платформы.
3. **Минимальный native loop** — небольшой собственный цикл только как контроль сложности и зависимостей, а не заранее выбранная реализация.

Каждый прототип оценивается по одинаковым критериям:

1. **Управление памятью:** явное состояние вместо скрытой истории; управление контекстом остаётся на стороне платформы
2. **Инструменты:** типизированный контракт инструментов с явными границами, независимый от того, какая модель их вызывает
3. **Цикл:** управляемые шаги с явной передачей управления, без скрытого обхода платформенных проверок
4. **Модель-инвариантность:** вызов модели проходит через `ModelGateway` ([`ADR_003`](adr_003_model_provider_interface.md#adr_003)) — смена модели или её поставщика не требует смены среды
5. **Безопасность:** изоляция инструментов через отдельные узлы и явные границы состояния
6. **Эволюция:** `RuntimePort` позволяет сравнивать и заменять среды без изменения ядра.

Документ остаётся `proposed` до сравнительного evidence и решения владельца. Он не разрешает заранее использовать LangGraph/LangChain во всех этапах [`m02`](../milestones.md#m02)–[`m06`](../milestones.md#m06).

## 4. Альтернативы

| Вариант | Преимущества | Недостатки |
|---------|-------------|-----------|
| **LangGraph (кандидат)** | Явный граф состояний, модель-инвариантен по конструкции, зрелая экосистема адаптеров моделей | Больше начальной сложности настройки, чем у линейного цикла |
| **Hermes Agent (кандидат)** | Готовая агентная среда и практический путь к запрошенному владельцем Hermes-варианту | Нужно доказать модель-инвариантность, прозрачность состояния и отсутствие обхода OwnerControl |
| **Минимальный native loop (кандидат)** | Минимум зависимостей, полный контроль и эталон для сравнения сложности | Больше собственной ответственности за повторы, состояние, инструменты и ошибки |
| LangChain (без LangGraph) | Тот же модель-агностичный слой моделей, проще для линейных сценариев | Менее явное управление ветвлением цикла, чем в LangGraph |
| Claude Agent SDK | Явное управление циклом, качество планирования | Не инвариантен к модели: цикл жёстко вызывает Anthropic API изнутри — не проходит явное требование владельца |
| AutoGen | Многоагентные архитектуры | Излишняя сложность для одного агента |

## 5. Последствия

**Положительные:**
- Явное управление шагами агента (для SEC_CTL)
- Модель-инвариантность обеспечена архитектурой кандидата, а не только границей `RuntimePort`
- Зрелая, широко поддерживаемая экосистема адаптеров моделей и инструментов
- `RuntimePort` остаётся фреймворк-агностичным

**Отрицательные:**
- Привязка к LangGraph/LangChain как фреймворку (в рамках `RuntimePort`)
- Нужно изучить специфику графовой модели состояния
- Часть "магии" абстракций LangChain требует внимательной проверки на скрытые побочные вызовы

## 6. Проверка

- [ ] LangGraph, Hermes Agent и минимальный native loop проверены на одном сценарии.
- [ ] `RuntimePort` не содержит импортов конкретного SDK.
- [ ] Каждый прототип проходит цикл план → инструмент → проверка → следующий шаг с двумя разными поставщиками модели без изменения среды — это и есть доказательство модель-инвариантности, а не только заявление.
- [ ] Каждый прототип выполняет цикл план → инструмент → проверка → следующий шаг.
- [ ] Проверены отмена, изоляция инструментов и явное управление состоянием.
- [ ] Evidence и решение владельца зафиксированы до смены `decision_state`.
