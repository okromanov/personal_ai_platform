# ADR_002 — Граница платформы и среды агента

## 1. Назначение

Зафиксировать, какие обязанности принадлежат ядру платформы и не передаются выбранной среде агента.

## 2. Контекст

Готовая среда агента может ускорить реализацию. Однако контроль владельца, постоянное состояние и границы безопасности не должны становиться неотделимыми от конкретной программной основы.

## 3. Решение

В границе платформы остаются:

- проверка личности и правил владельца;
- каноническое состояние задач;
- границы постоянных данных и памяти;
- контракты шлюзов инструментов и моделей.

Сменная среда агента подключается через `RuntimePort`. Канонический состав компонентов определяет [`architecture_baseline.md`](../specifications/architecture_baseline.md). Этот ADR фиксирует причину выбора границы и не создаёт второй источник архитектурных обязанностей.

Конкретная программная основа не фиксируется этим ADR и выбирается сравнением в момент реализации.

## 4. Альтернативы

- Передать состояние и правила платформы внешней основе — быстрее вначале, но создаёт критическую зависимость.
- Сразу построить собственную универсальную среду — преждевременная сложность без доказанной пользы.
- Стабильная граница платформы и заменяемый переходный слой — выбранный вариант.

## 5. Последствия

- программную основу можно сменить без миграции контроля владельца и канонической памяти;
- требуется небольшой контракт переходного слоя и его проверки;
- нельзя добавлять абстракции только ради гипотетической миграции: `RuntimePort` расширяется по реальным сценариям.

## 6. Проверка

Тестовый переходный слой может выполнить базовый контракт задачи без доступа к главным секретам, аварийному выключателю и постоянному состоянию платформы.
