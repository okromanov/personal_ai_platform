# ADR_003 — Интерфейс поставщика моделей

## 1. Назначение

Зафиксировать контракт между платформой и поставщиком модели, не зависящий от конкретного SDK.

## 2. Контекст

Модели и поставщики меняются быстрее прикладных сценариев. Прямые вызовы SDK поставщика из ядра затрудняют замену, резервный путь, тестирование и исполнение правил данных.

## 3. Решение

Использовать единый контракт `ModelProvider` для нормализованных запроса, ответа, ошибки, ограничения времени и доступных показателей использования. Конкретные поставщик и модель выбираются настройкой и правилами до вызова переходного слоя.

## 4. Альтернативы

- Прямые вызовы SDK из прикладного кода проще только на старте, но создают сильную связанность.
- Обязательный универсальный внешний посредник может быть полезен позже, но не должен становиться необходимой зависимостью без причины.

## 5. Последствия

- замена поставщика не меняет контракты задач и каналов;
- резервный путь и выбор модели добавляются без переписывания прикладного кода;
- тестовый поставщик позволяет детерминированно проверять ядро без сетевого вызова.

## 6. Проверка

Проверки контракта подтверждают одинаковую обработку успеха, ошибки и ограничения времени как минимум для тестового переходного слоя и выбранной рабочей реализации.
