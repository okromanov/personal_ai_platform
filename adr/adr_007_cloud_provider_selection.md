# ADR_007 — Выбор облачного провайдера

## 1. Назначение

Зафиксировать AWS как кандидата для сравнения площадок размещения в [`m02`](../milestones.md#m02).

## 2. Контекст

V1 требует:
- регулярно доступный и восстанавливаемый сервис ([`BR_005`](../specifications/business_requirements.md#br_005));
- наблюдаемую версию, состояние и стоимость ([`SYS_024`](../specifications/system_specification.md#sys_024), [`INF_REQ_013`](../specifications/infrastructure_baseline.md#inf_req_013));
- переносимое развёртывание ([`SYS_027`](../specifications/system_specification.md#sys_027), [`INF_REQ_001`](../specifications/infrastructure_baseline.md#inf_req_001), [`INF_REQ_014`](../specifications/infrastructure_baseline.md#inf_req_014));
- устойчивое постоянное состояние ([`INF_REQ_008`](../specifications/infrastructure_baseline.md#inf_req_008));
- проверяемое резервное копирование, восстановление и откат ([`SYS_025`](../specifications/system_specification.md#sys_025), [`INF_REQ_009`](../specifications/infrastructure_baseline.md#inf_req_009), [`INF_REQ_011`](../specifications/infrastructure_baseline.md#inf_req_011)).

Облачный провайдер должен обеспечить:
- Доступ по API из Python приложения
- Гибкость масштабирования (от минимума при разработке к [`m06`](../milestones.md#m06))
- Ценообразование прозрачно для одного пользователя
- Возможность экспорта данных без привязки к поставщику

Владелец работает из России: часть иностранных площадок (в т.ч. Hetzner) требует VPN для регистрации и управления и может не принять доступную владельцу карту. Это не аргумент за размещение в России как таковое — сервер вне России структурно снимает проблему доступа к иностранным API моделей ([`ADR_005`](adr_005_first_model_provider_selection.md#adr_005)) без VPN на стороне самого сервиса. Это аргумент за то, чтобы держать два разных, явно поименованных сценария вместо одного «универсального» решения: основной — за пределами России, резервный — полностью в российской юрисдикции на случай, если основной станет недоступен или неоплачиваем.

## 3. Предлагаемое решение

Сравнить в [`m02`](../milestones.md#m02) два сценария, а не единственного провайдера:

**Сценарий A — основной, вне России:** включить **Hetzner** (простой и прозрачный по цене VPS, предпочтителен для одного пользователя перед AWS — см. §4) в сравнение площадок и проверить минимальный контур:

1. **Вычисления:** VPS с закреплённой версией ОС для [`dockerfile`](../dockerfile) ([`TASK_008`](../work/tasks/task_008_inf_001.md))
2. **Хранилище данных:** управляемая или самостоятельно развёрнутая PostgreSQL
3. **Долговременное хранилище:** объектное хранилище провайдера или совместимый S3-API для резервных копий и экспорта
4. **Управление секретами:** см. [`ADR_009`](adr_009_secret_management_strategy.md#adr_009), без привязки к конкретному облаку
5. **Бюджет:** прозрачный тариф провайдера, без необходимости отдельного инструмента контроля расходов

**Сценарий B — резервный, полностью в РФ:** включить **Selectel** (российский облачный провайдер, оплата в рублях, без VPN для управления) на случай недоступности или неоплачиваемости сценария A. Сценарий B предполагает канал доступа к модели тоже в РФ-юрисдикции ([`ADR_005`](adr_005_first_model_provider_selection.md#adr_005)) — смешивать «сервер в РФ» с «прямой иностранный API модели» бессмысленно, задача сценария B не решается наполовину.

**Гипотеза для проверки (сценарий A, Hetzner):**
- Простой, прозрачный по цене, достаточный для одного пользователя контур
- Хорошая поддержка Python
- Сервер вне России снимает проблему доступа к иностранным API моделей
- Возможность экспорта данных в стандартных форматах (SQL, JSON)

Решение о провайдере в каждом сценарии принимается только после сравнения стоимости, сложности, восстановления и переносимости минимум с одной альтернативой в этом же сценарии. До этого ни Hetzner, ни Selectel не являются обязательной средой [`m02`](../milestones.md#m02)–[`m06`](../milestones.md#m06).

## 4. Альтернативы

| Вариант | Преимущества | Недостатки |
|---------|-------------|-----------|
| **Hetzner (кандидат, сценарий A)** | Просто, прозрачно по цене, достаточно для одного пользователя | Регистрация/управление могут требовать VPN; приём карты владельца не гарантирован — проверить заранее |
| **Selectel (кандидат, сценарий B)** | Полностью в РФ-юрисдикции, оплата в рублях, без VPN | Резервный контур, а не замена сценария A: не решает доступ к иностранным моделям в одиночку |
| AWS | Мощный, гибкий, надёжный | Сложен на старте, может быть дорогим без оптимизации; верификация карты/телефона по стране биллинга может быть строже, чем у простого VPS — не даёт преимуществ над Hetzner для одного пользователя |
| GCP | Хорошее ценообразование для data, ML интеграции | Меньше знакомства, другие API |
| Azure | Интеграция с Microsoft ecosystem | Менее полезно для одного пользователя |
| Heroku | Простой deploy, встроенная BD | Дороже на длинной дистанции, менее контроля |
| DigitalOcean | Просто и дешево | Та же проблема доступа/оплаты для владельца, что и у Hetzner — сравнить наравне с ним в сценарии A |
| На своем сервере | Максимальная независимость | Огромная работа, нужно управлять всем |

## 5. Последствия

**Положительные:**
- Два явных сценария (вне РФ / в РФ) вместо одного решения, которое ломается при первом же ограничении доступа или оплаты
- Hetzner проще и дешевле AWS для одного пользователя
- Selectel закрывает [`BR_038`](../specifications/business_requirements.md#br_038)/[`BR_039`](../specifications/business_requirements.md#br_039) (переносимое развёртывание, локальный резервный контур) практическим, а не гипотетическим путём
- Данные можно экспортировать в стандартных форматах независимо от сценария

**Отрицательные:**
- Поддержка двух сценариев вместо одного увеличивает объём работы по развёртыванию и документации
- Регистрация/управление Hetzner может потребовать VPN, а приём карты владельца не гарантирован ни у одного из кандидатов — оба пункта нужно проверить до принятия решения
- Sценарий B работает только в паре с РФ-каналом доступа к модели — половинчатое решение (сервер в РФ + иностранный API напрямую) не закрывает исходную проблему

## 6. Проверка

- [ ] Hetzner и минимум одна альтернативная площадка сценария A (например, DigitalOcean) оценены по единой scorecard.
- [ ] Selectel оценён отдельно как резервный сценарий B, включая совместимость с РФ-каналом доступа к модели ([`ADR_005`](adr_005_first_model_provider_selection.md#adr_005)).
- [ ] Для каждого кандидата подтверждено, принимает ли он доступную владельцу карту, и требует ли регистрация/управление VPN.
- [ ] Для каждого кандидата проверены стоимость, сеть, секреты, backup/restore и переносимость.
- [ ] Минимальный прототип развёртывания воспроизводим в обоих сценариях.
- [ ] Документирован экспорт данных и конфигурации.
- [ ] Evidence и решение владельца зафиксированы до смены `decision_state`.
