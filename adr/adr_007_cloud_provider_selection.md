# ADR_007 — Выбор облачного провайдера

## 1. Назначение

Зафиксировать Hetzner и DigitalOcean как два кандидата сценария A (вне России) и Selectel как кандидата отдельного резервного сценария B (в РФ) для сравнения площадок размещения в [`m02`](../milestones.md#m02).

## 2. Контекст

V1 требует:
- регулярно доступный и восстанавливаемый сервис ([`BR_005`](../specifications/business_requirements.md#br_005));
- наблюдаемую версию, состояние и стоимость ([`SYS_024`](../specifications/system_specification.md#sys_024), [`INF_REQ_013`](../specifications/infrastructure_baseline.md#inf_req_013));
- переносимое развёртывание ([`SYS_027`](../specifications/system_specification.md#sys_027), [`INF_REQ_001`](../specifications/infrastructure_baseline.md#inf_req_001), [`INF_REQ_014`](../specifications/infrastructure_baseline.md#inf_req_014));
- устойчивое постоянное состояние ([`INF_REQ_008`](../specifications/infrastructure_baseline.md#inf_req_008));
- проверяемое резервное копирование, восстановление и откат ([`SYS_025`](../specifications/system_specification.md#sys_025), [`INF_REQ_009`](../specifications/infrastructure_baseline.md#inf_req_009), [`INF_REQ_011`](../specifications/infrastructure_baseline.md#inf_req_011)).

Облачный провайдер должен обеспечить:
- Доступ по API из Python приложения
- Гибкость масштабирования (от минимума при разработке к [`m06`](../milestones.md#m06))
- Ценообразование прозрачно для одного пользователя
- Возможность экспорта данных без привязки к поставщику

Владелец работает из России: иностранная площадка может потребовать VPN для регистрации и управления и может не принять доступную владельцу карту. Это не аргумент за размещение в России как таковое — сервер вне России структурно снимает проблему доступа к иностранным API моделей ([`ADR_005`](adr_005_first_model_provider_selection.md#adr_005)) без VPN на стороне самого сервиса. Это аргумент за то, чтобы держать два разных, явно поименованных сценария вместо одного «универсального» решения: основной — за пределами России (нужно практически проверить минимум два сопоставимых VPS-провайдера, а не закреплять первого кандидата по описанию сайта), резервный — полностью в российской юрисдикции на случай, если основной станет недоступен или неоплачиваем.

## 3. Предлагаемое решение

Сравнить в [`m02`](../milestones.md#m02) два сценария, а не единственного провайдера:

**Сценарий A — основной, вне России:** сравнить **Hetzner** и **DigitalOcean** по одной scorecard, затем развернуть минимальный живой контур у победителя:

1. **Вычисления:** VPS с закреплённой версией ОС для [`dockerfile`](../dockerfile) ([`TASK_008`](../work/tasks/task_008_inf_001.md))
2. **Сеть:** исходящий HTTPS к Telegram и выбранному model provider; inbound доступ ограничен SSH/VPN-политикой
3. **Управление секретами:** см. [`ADR_009`](adr_009_secret_management_strategy.md#adr_009), без привязки к конкретному облаку
4. **Развёртывание:** одинаковый versioned Docker image, health-check и rollback
5. **Переносимость:** одинаковые данные и конфигурация экспортируются без provider-specific формата
6. **Бюджет и доступ:** подтверждены реальная цена, доступная владельцу оплата и необходимость VPN для регистрации/управления

Решение внутри сценария A принимается после scorecard и практической проверки доступа к обоим провайдерам. Платная VM создаётся у выбранного победителя; у второго кандидата достаточно подтверждённой регистрации, цены и воспроизводимой конфигурации без постоянной оплачиваемой VM.

**Сценарий B — резервный, полностью в РФ:** включить **Selectel** (российский облачный провайдер, оплата в рублях, без VPN для управления) на случай недоступности или неоплачиваемости сценария A. Сценарий B предполагает канал доступа к модели тоже в РФ-юрисдикции ([`ADR_005`](adr_005_first_model_provider_selection.md#adr_005)) — смешивать «сервер в РФ» с «прямой иностранный API модели» бессмысленно, задача сценария B не решается наполовину. Сценарий B остаётся в бэклоге: он оценивается отдельно, но реальный live-деплой у Selectel откладывается до проверки сценария A и создания резервной копии данных.

До решения ни Hetzner, ни DigitalOcean, ни Selectel не являются обязательной средой [`m02`](../milestones.md#m02)–[`m06`](../milestones.md#m06).

## 4. Альтернативы

| Вариант | Преимущества | Недостатки |
|---------|-------------|-----------|
| **Hetzner (кандидат, сценарий A)** | Простой VPS и прозрачная цена, достаточные для одного пользователя | Регистрация/управление могут требовать VPN; доступная владельцу оплата должна быть проверена |
| **DigitalOcean (кандидат, сценарий A)** | Простой интерфейс, понятные Droplets и распространённая документация | Обычно дороже сопоставимого Hetzner; регистрация и оплата также требуют практической проверки |
| **Selectel (кандидат, сценарий B)** | Полностью в РФ-юрисдикции, оплата в рублях, без VPN | Резервный контур, а не замена сценария A: не решает доступ к иностранным моделям в одиночку; live-деплой отложен до проверки сценария A |
| AWS | Мощный, гибкий, надёжный | Сложен на старте, может быть дорогим без оптимизации; верификация карты/телефона по стране биллинга может быть строже, чем у простого VPS — не даёт преимуществ над Hetzner для одного пользователя |
| GCP | Хорошее ценообразование для data, ML интеграции | Меньше знакомства, другие API |
| Azure | Интеграция с Microsoft ecosystem | Менее полезно для одного пользователя |
| Heroku | Простой deploy, встроенная BD | Дороже на длинной дистанции, менее контроля |
| На своем сервере | Максимальная независимость | Огромная работа, нужно управлять всем |

## 5. Последствия

**Положительные:**
- Два явных сценария (вне РФ / в РФ) вместо одного решения, которое ломается при первом же ограничении доступа или оплаты
- Два сопоставимых зарубежных кандидата сценария A вместо выбора по маркетинговому описанию — победитель определяется реальной доступностью, ценой и воспроизводимостью для владельца
- Selectel закрывает [`BR_038`](../specifications/business_requirements.md#br_038)/[`BR_039`](../specifications/business_requirements.md#br_039) (переносимое развёртывание, локальный резервный контур) практическим, а не гипотетическим путём
- Данные можно экспортировать в стандартных форматах независимо от сценария

**Отрицательные:**
- Поддержка двух сценариев вместо одного увеличивает объём работы по развёртыванию и документации
- Нужно проверить регистрацию и оплату у обоих кандидатов сценария A
- Сценарий B работает только в паре с РФ-каналом доступа к модели — половинчатое решение (сервер в РФ + иностранный API напрямую) не закрывает исходную проблему
- Различия provider API нельзя переносить в прикладной контракт развёртывания

## 6. Проверка

- [ ] Hetzner и DigitalOcean (сценарий A) оценены по единой scorecard.
- [ ] Selectel (сценарий B) оценён отдельно как резервный сценарий, включая совместимость с РФ-каналом доступа к модели ([`ADR_005`](adr_005_first_model_provider_selection.md#adr_005)).
- [ ] Для каждого кандидата подтверждено, принимает ли он доступную владельцу карту и требует ли регистрация/управление VPN.
- [ ] Для каждого кандидата проверены стоимость, сеть, секреты, backup/restore и переносимость.
- [ ] У победителя сценария A выполнен минимальный live deployment; для второго кандидата сценария A подтверждена воспроизводимая эквивалентная конфигурация без постоянной VM; сценарий B оценён без обязательного live-деплоя до завершения проверки сценария A.
- [ ] Документирован экспорт данных и конфигурации.
- [ ] Evidence и решение владельца зафиксированы до смены `decision_state`.
