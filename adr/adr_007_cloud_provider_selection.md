# ADR_007 — Выбор облачного провайдера

## 1. Назначение

Зафиксировать Hetzner и DigitalOcean как два кандидата для сравнения площадок размещения в [`m02`](../milestones.md#m02).

## 2. Контекст

V1 требует:
- регулярно доступный и восстанавливаемый сервис ([`BR_005`](../specifications/business_requirements.md#br_005));
- наблюдаемую версию, состояние и стоимость ([`SYS_024`](../specifications/system_specification.md#sys_024), [`INF_REQ_013`](../specifications/infrastructure_baseline.md#inf_req_013));
- переносимое развёртывание ([`SYS_027`](../specifications/system_specification.md#sys_027), [`INF_REQ_001`](../specifications/infrastructure_baseline.md#inf_req_001), [`INF_REQ_014`](../specifications/infrastructure_baseline.md#inf_req_014));
- устойчивое постоянное состояние ([`INF_REQ_008`](../specifications/infrastructure_baseline.md#inf_req_008));
- проверяемое резервное копирование, восстановление и откат ([`SYS_025`](../specifications/system_specification.md#sys_025), [`INF_REQ_009`](../specifications/infrastructure_baseline.md#inf_req_009), [`INF_REQ_011`](../specifications/infrastructure_baseline.md#inf_req_011)).

Облачный провайдер должен обеспечить:
- Доступ по API из Python приложения
- Гибкость масштабирования (от минимума при разработке к [`m06`](../milestones.md#m06))
- Ценообразование прозрачно для одного пользователя
- Возможность экспорта данных без привязки к поставщику

Владелец работает из России: иностранная площадка может потребовать VPN для регистрации и управления и может не принять доступную владельцу карту. Сервер вне России структурно снимает проблему доступа к иностранным API моделей ([`ADR_005`](adr_005_first_model_provider_selection.md#adr_005)) без постоянного VPN на стороне самого сервиса. Поэтому до выбора нужно практически проверить два сопоставимых зарубежных VPS-провайдера, а не закреплять первого кандидата по описанию сайта.

## 3. Предлагаемое решение

Сравнить в [`m02`](../milestones.md#m02) **Hetzner** и **DigitalOcean** по одной scorecard, затем развернуть минимальный живой контур у победителя:

1. **Вычисления:** VPS с закреплённой версией ОС для [`dockerfile`](../dockerfile) ([`TASK_008`](../work/tasks/task_008_inf_001.md))
2. **Сеть:** исходящий HTTPS к Telegram и выбранному model provider; inbound доступ ограничен SSH/VPN-политикой
3. **Управление секретами:** см. [`ADR_009`](adr_009_secret_management_strategy.md#adr_009), без привязки к конкретному облаку
4. **Развёртывание:** одинаковый versioned Docker image, health-check и rollback
5. **Переносимость:** одинаковые данные и конфигурация экспортируются без provider-specific формата
6. **Бюджет и доступ:** подтверждены реальная цена, доступная владельцу оплата и необходимость VPN для регистрации/управления

Решение принимается после scorecard и практической проверки доступа к обоим провайдерам. Платная VM создаётся у выбранного победителя; у второго кандидата достаточно подтверждённой регистрации, цены и воспроизводимой конфигурации без постоянной оплачиваемой VM. До решения ни Hetzner, ни DigitalOcean не являются обязательной средой [`m02`](../milestones.md#m02)–[`m06`](../milestones.md#m06).

## 4. Альтернативы

| Вариант | Преимущества | Недостатки |
|---------|-------------|-----------|
| **Hetzner (кандидат)** | Простой VPS и прозрачная цена, достаточные для одного пользователя | Регистрация/управление могут требовать VPN; доступная владельцу оплата должна быть проверена |
| **DigitalOcean (кандидат)** | Простой интерфейс, понятные Droplets и распространённая документация | Обычно дороже сопоставимого Hetzner; регистрация и оплата также требуют практической проверки |
| AWS | Мощный, гибкий, надёжный | Сложен на старте, может быть дорогим без оптимизации; верификация карты/телефона по стране биллинга может быть строже, чем у простого VPS — не даёт преимуществ над Hetzner для одного пользователя |
| GCP | Хорошее ценообразование для data, ML интеграции | Меньше знакомства, другие API |
| Azure | Интеграция с Microsoft ecosystem | Менее полезно для одного пользователя |
| Heroku | Простой deploy, встроенная BD | Дороже на длинной дистанции, менее контроля |
| Selectel | Оплата в рублях и российская юрисдикция | Не участвует в выборе [`m02`](../milestones.md#m02); сам по себе не решает прямой доступ к иностранным model API |
| На своем сервере | Максимальная независимость | Огромная работа, нужно управлять всем |

## 5. Последствия

**Положительные:**
- Два сопоставимых зарубежных кандидата вместо выбора по маркетинговому описанию
- Победитель определяется реальной доступностью, ценой и воспроизводимостью для владельца
- Данные можно экспортировать в стандартных форматах независимо от сценария

**Отрицательные:**
- Нужно проверить регистрацию и оплату у двух провайдеров
- В [`m02`](../milestones.md#m02) не создаётся живой российский резервный контур
- Различия provider API нельзя переносить в прикладной контракт развёртывания

## 6. Проверка

- [ ] Hetzner и DigitalOcean оценены по единой scorecard.
- [ ] Для обоих кандидатов подтверждено, принимает ли он доступную владельцу карту и требует ли регистрация/управление VPN.
- [ ] Для каждого кандидата проверены стоимость, сеть, секреты, backup/restore и переносимость.
- [ ] У победителя выполнен минимальный live deployment; для второго кандидата подтверждена воспроизводимая эквивалентная конфигурация без постоянной VM.
- [ ] Документирован экспорт данных и конфигурации.
- [ ] Evidence и решение владельца зафиксированы до смены `decision_state`.
