# ADR_004 — Структурированные события задачи

## 1. Назначение

Зафиксировать минимальную переносимую модель технических событий, достаточную для диагностики, жизненного цикла задач и будущей трассировки без зависимости от конкретного средства наблюдения.

## 2. Контекст

Свободный текст журналов плохо подходит для автоматического анализа и восстановления. Полный набор распределённой трассировки заранее избыточен.

## 3. Решение

Каждая исполняемая задача имеет `runtime_task_id`. Существенные переходы состояния, вызовы моделей и инструментов, решения правил, повторы, контрольные точки и ошибки создают структурированные события. Событие содержит время, тип, компонент, операцию, результат и безопасные технические атрибуты.

Схема допускает `trace_id`, `span_id`, `parent_span_id`, задержку, использование и метаданные повтора или возобновления, когда соответствующая сущность реально появляется. Полное пользовательское содержимое и секреты по умолчанию не журналируются.

## 4. Альтернативы

- Только свободный текст — недостаточно структурирован для автоматического анализа.
- Полное средство трассировки как обязательная часть ядра — преждевременная инфраструктура.
- Переносимая модель событий — выбранный вариант.

## 5. Последствия

- задачу можно диагностировать по одному идентификатору;
- средство журналирования и метрик заменяемо;
- модель событий может стать основой анализа выполнения;
- обязательная минимизация чувствительных данных остаётся отдельной мерой безопасности.

## 6. Проверка

Автоматические тесты проверяют ключевые события состояния, связь по `runtime_task_id`, нормализованные ошибки и отсутствие известных секретов в стандартном событии.
