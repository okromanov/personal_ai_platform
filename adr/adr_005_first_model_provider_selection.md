# ADR_005 — Выбор первого поставщика модели

## 1. Назначение

Зафиксировать набор кандидатов на роль первого поставщика модели для сравнения в [`m02`](../milestones.md#m02), согласованный с владельцем: Anthropic Claude, OpenAI GPT, Google Gemini и отечественные модели (YandexGPT, GigaChat). Ни один вариант не предпочтён этим документом — сравнение и решение владельца происходят отдельно, после этого ADR.

## 2. Контекст

[`ADR_003`](adr_003_model_provider_interface.md#adr_003) определяет интерфейс `ModelProvider` для независимости от поставщика. Первоначальная реализация должна работать с конкретной моделью, но сама модель и канал доступа к ней — два разных решения внутри одного ADR, а не два отдельных ADR: модель может остаться неизменной, даже если меняется способ до неё достучаться, и наоборот.

Владелец работает из России: прямой API Anthropic/OpenAI недоступен без VPN, а оплата иностранной картой не гарантирована. Это не аргумент против иностранных моделей как таковых — для них уже есть VPN-независимые каналы доступа (посреднический мультипровайдерный API вроде OpenRouter, российский посреднический API-провайдер). Это аргумент за то, чтобы наравне с иностранными моделями сравнивать и отечественные (YandexGPT, GigaChat): они снимают вопрос канала доступа полностью, но могут отличаться по качеству рассуждения и совместимости с требованиями памяти/контекста ([`BR_033`](../specifications/business_requirements.md#br_033), [`BR_034`](../specifications/business_requirements.md#br_034)).

## 3. Предлагаемое решение

Сравнить в [`m02`](../milestones.md#m02) четыре кандидата, каждый через `ModelProvider`, без прямых вызовов SDK конкретного поставщика в бизнес-коде:

1. **Anthropic Claude (кандидат)** — доступ через прямой API либо канал без VPN (OpenRouter, российский посреднический API-провайдер).
2. **OpenAI GPT (кандидат)** — та же развилка доступа, что и у Claude: прямой API требует VPN, канал без VPN сравнивается так же.
3. **Google Gemini (кандидат)** — та же развилка доступа: прямой API vs канал без VPN.
4. **Отечественные модели — YandexGPT/GigaChat (кандидат)** — нативно доступны из России без VPN и с оплатой в рублях; конкретный поставщик среди двух определяется отдельным evidence-сравнением, а не фиксируется этим ADR.

Общее для всех кандидатов:
- **Интерфейс:** `ModelProvider` контракт, конфигурация (ключ, модель, канал доступа) — через переменные окружения.
- **Резервный путь:** контракт позволяет добавить второго поставщика модели или сменить канал доступа позже без переписывания ядра.
- **Тестирование:** тестовый mock-поставщик для детерминированных проверок, не зависящий от выбора среди кандидатов.

Переход `proposed → accepted` разрешён только после сравнительного evidence по критериям [`m02`](../milestones.md#m02) и явного решения владельца. До этого документ не означает выбор ни одного из кандидатов для [`m02`](../milestones.md#m02)–[`m06`](../milestones.md#m06).

## 4. Альтернативы

| Вариант | Преимущества | Недостатки |
|---------|-------------|-----------|
| **Claude (кандидат)** | Качество рассуждений, совместимость, политика данных | Прямой API недоступен из России без VPN; оплата иностранной картой не гарантирована |
| **GPT (кандидат)** | Зрелый API, широкая экосистема инструментов | Та же проблема доступа/оплаты, что и у Claude |
| **Gemini (кандидат)** | Длинный контекст, интеграция с Google-инфраструктурой | Та же проблема доступа/оплаты; меньше опыта использования в проекте |
| **Отечественные модели — YandexGPT/GigaChat (кандидат)** | Нативный доступ из России без VPN, оплата в рублях, отсутствие прямого договора с иностранным поставщиком | Качество рассуждения и совместимость с требованиями к памяти/контексту не проверены; устойчивость и политика конкретного поставщика требуют отдельного evidence-сравнения |
| Open-source модель (самостоятельный хостинг) | Полная независимость от внешнего поставщика | Требуются собственная инфраструктура и проверка качества — вне бюджета одного пользователя на первом этапе |
| Не выбирать сейчас | Максимальная гибкость | Блокирует разработку m02 |

Для трёх иностранных кандидатов (Claude, GPT, Gemini) канал доступа — отдельная развилка внутри каждого: прямой API (требует VPN) либо посреднический канал (OpenRouter, российский посреднический API-провайдер) — сравнивается одинаково для всех трёх, а не только для Claude.

## 5. Последствия

**Положительные:**
- [`ADR_003`](adr_003_model_provider_interface.md#adr_003) контракт остаётся чистым (не привязан к конкретному кандидату)
- [`m02`](../milestones.md#m02) получает четыре реальных кандидата для воспроизводимого сравнения, включая вариант без проблемы доступа (отечественные модели)
- Резервный поставщик добавляется через тот же интерфейс независимо от исхода сравнения

**Отрицательные:**
- Сравнение четырёх кандидатов и до двух каналов доступа для трёх из них — больше evidence-работы, чем сравнение одного кандидата
- Затраты на API нескольких поставщиков во время сравнения
- Отечественные модели ещё не проверены на реальных задачах проекта — качество неизвестно до сравнения

## 6. Проверка

- [ ] Все четыре кандидата (Claude, GPT, Gemini, отечественные модели) проверены на одном сценарии и одной scorecard.
- [ ] Для каждого из трёх иностранных кандидатов сравнены минимум два канала доступа (прямой API и посреднический канал без VPN) по доступности, оплате и задержке.
- [ ] Для отечественных моделей подтверждён нативный доступ из России без VPN и оплата в рублях.
- [ ] `ModelProvider` работает с каждым проверенным кандидатом без прямых импортов SDK в бизнес-коде.
- [ ] Переменные окружения позволяют менять ключ, модель и канал доступа без изменения кода.
- [ ] Mock-поставщик проходит тот же контракт.
- [ ] Evidence и решение владельца зафиксированы до смены `decision_state`.
